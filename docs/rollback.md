# Резервні копії та rollback

## Стратегія M4

Перед кожною write-операцією ResolveBridge:

1. перевіряє аргументи та media allowlist;
2. зберігає поточний проєкт через документований `SaveProject`;
3. експортує `.drp` через документований `ExportProject`;
4. виконує рівно одну дозволену операцію;
5. записує idempotency receipt після успіху.

Якщо збереження або експорт не вдалися, зміна не виконується. Успішна відповідь
містить `backup_path`. Якщо Resolve відхилив операцію вже після експорту,
`backup_path` повертається в `error.details`.

Резервні копії зберігаються в:

```text
%LOCALAPPDATA%\DaVinciResolveAgent\runtime\backups\
```

## Чому немає автоматичного restore

M4 не закриває і не замінює відкритий проєкт автоматично. Відновлення `.drp`
може змінити активний проєкт або створити конфлікт імен, тому воно залишається
явною дією користувача в Resolve Project Manager.

Для rollback:

1. припини надсилати write-команди;
2. знайди `.drp` за `backup_path`;
3. відкрий Project Manager у Resolve;
4. імпортуй резервний `.drp` під окремим ім'ям;
5. перевір результат перед видаленням або заміною поточного проєкту.

`uninstall.ps1` типово зберігає каталог backups. Його видалення можливе лише з
явним параметром:

```powershell
.\installer\uninstall.ps1 -PreserveBackups $false
```

## Ідемпотентність

Для повторюваної операції передавай той самий `idempotency_key`. Повтор із тим
самим ключем і тими самими аргументами поверне збережений результат без
дублювання зміни. Повторне використання ключа з іншою дією або аргументами
завершиться помилкою `IDEMPOTENCY_CONFLICT`.
